## 2026-08-26 — เพิ่ม `surprise_driven` (regime สำหรับวินิจฉัยเท่านั้น ไม่นับคะแนน)

### เกิดอะไรขึ้น

KC4 fail (ρ = 0.1056 เทียบเกณฑ์ > 0.25) — คือ "surprise ไม่สัมพันธ์กับความสำคัญจริง"
ซึ่งตาม §7.4 แปลว่า **สมมติฐานหลักของโปรเจกต์ผิด**

ตรวจต่อพบกลไกที่ทำให้เป็นแบบนั้น อยู่ใน `generator.py`:

```python
revise = is_first_sight or (rng_revise.random() < cfg.fact_revision_rate)
```

การตัดสินว่า observation ไหนกลายเป็น "หลักฐานปัจจุบัน" ของ fact เป็น**การทอยเหรียญอิสระ**
ไม่เกี่ยวกับ surprise ของ observation นั้นเลย

ผลที่วัดได้บน `uniform / dev-01`:

```
surprise เฉลี่ยของ item ที่ query ต้องการ : 0.1850
surprise เฉลี่ยของ item ทั้งหมด          : 0.1657    <- แทบไม่ต่างกัน
item ที่ query ต้องการ ซึ่ง surprise ≥ 0.6 :   7.5%   <- S เก็บได้แค่นี้
```

เทียบกับ `long_gap` ที่ช่องว่างเวลาทำให้ confidence ตก → observation เกือบทุกตัว surprise สูง:

```
surprise เฉลี่ยของ item ที่ query ต้องการ : 1.0000
item ที่ query ต้องการ ซึ่ง surprise ≥ 0.6 : 100.0%
```

→ นี่คือเหตุผลที่ `S` ทำได้ 1.000 ใน long_gap แต่ทำได้ ~0.06 ใน uniform
   **คอขวดอยู่ที่ประตูตอน encode ไม่ใช่ตอน retrieve** — retrieve เก่งแค่ไหนก็ช่วยไม่ได้
   ถ้าของถูกทิ้งตั้งแต่แรก

### ทำไมถึงเรียกได้ว่าเป็นข้อบกพร่องของ generator (ไม่ใช่แค่ "S แพ้")

D-04 นิยามไว้เองว่า `surprise = 1 − confidence(predictor)`
ถ้าอย่างนั้น "ความเชื่อเกี่ยวกับ fact เปลี่ยน" ก็ควรหมายถึง "predictor ทายพลาด" โดยนิยาม

แต่โค้ดปัจจุบันให้ observation ที่มาซ้ำ ๆ แบบ**ยืนยันความเชื่อเดิม** (surprise 0.02)
กลายเป็นเฉลยของ query ได้ ทั้งที่ในโลกจำลองไม่มีอะไรเปลี่ยนเลย

benchmark จึงกำลังถามว่า *"หลักฐานล่าสุดคืออะไร"*
ส่วน thesis อ้างว่า *"สิ่งที่น่าประหลาดใจควรถูกจำ"* — คนละคำถามกัน

### สิ่งที่ทำ (และสิ่งที่จงใจไม่ทำ)

**ไม่ทำ:** ไม่แก้ regime เดิมทั้ง 7 ตัวแม้แต่ตัวเดียว
ค่าเริ่มต้นของ `revision_requires_surprise` คือ `False` → trace ทุกอันเหมือนเดิมทุกไบต์
ผลของ gate ยังคงถูกตัดสินด้วยข้อสอบชุดที่ประกาศไว้ก่อนเห็นคะแนน

**ทำ:** เพิ่ม flag `revision_requires_surprise` (+ `revision_surprise_floor = 0.5`)
และเพิ่ม regime ใหม่ชื่อ `surprise_driven` = `uniform` + flag นี้
เมื่อเปิด flag: ความเชื่อจะถูก revise ก็ต่อเมื่อ observation นั้น predictor ทายไม่ถูกจริง ๆ

`surprise_driven` อยู่ใน `DIAGNOSTIC_REGIMES` ของ `gate.py`
→ **ถูกกันออกจากทุก kill criterion** รายงานแยกต่างหากเสมอ

### เหตุผลที่ต้องกันออกจากการตัดสิน

regime นี้ถูกเพิ่ม **หลัง**เห็นว่า KC4 fail และถูกออกแบบมาให้สมมติฐานเป็นจริงในนั้น
ถ้าปล่อยให้มันขยับ gate ได้ = ออกข้อสอบเองหลังสอบเสร็จ ซึ่งผิด §15.7 ตรง ๆ

มันมีค่าในฐานะ**คำอธิบาย** ไม่ใช่ในฐานะ**คะแนน**:
มันตอบคำถามว่า "สมมติฐานผิด หรือ workload นี้ไม่ใช่ workload ที่สมมติฐานพูดถึง"
และต้องรายงานผลตามที่ออกมา ไม่ว่าจะออกมาทางไหน

### สิ่งที่ยังต้องให้ Nin ตัดสิน

ตัวเลขบอกได้แค่ว่ากลไกเป็นยังไง ตัดสินแทนไม่ได้ว่าอันไหนคือ "โลกจริง":

- **(ก)** workload ที่ SomaOS ตั้งใจจะเก่ง คือแบบ `surprise_driven` (ความเชื่อเปลี่ยนเมื่อเจอของที่ขัดความคาดหมาย)
  → regime เดิมออกแบบไม่ตรงกับสิ่งที่จะทดสอบ ต้องประกาศชุดข้อสอบใหม่ **ก่อน**รันรอบต่อไป
- **(ข)** "ถามหาหลักฐานล่าสุด" เป็น workload ที่พบจริงและสำคัญ
  → KC4 เป็นจริง สมมติฐานผิดสำหรับ workload กลุ่มนี้ ต้องรายงานตรง ๆ ตาม §7.4

ถ้าเลือก (ก) ต้อง **pre-register ชุด regime ใหม่และ seed ใหม่ก่อนดูผล** ไม่งั้นก็เป็นการเลือกข้อสอบที่ตัวเองทำได้อยู่ดี
