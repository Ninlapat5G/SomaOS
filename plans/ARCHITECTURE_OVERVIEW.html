ทำไมถึงเลือก binary

binary ทำลาย “ชิ้นไหนกันแน่” แต่รักษา “มันเป็นเรื่องแนวไหน” ไว้เกือบครบ — นี่ไม่ใช่ผลข้างเคียง มันคือเหตุผลที่เลือก เพราะสิ่งที่มันทำลายคือสิ่งที่ ควร ถูกทำลายก่อน (verbatim) และสิ่งที่มันรักษาไว้คือสิ่งที่ ควร อยู่รอด (gist) = fuzzy-trace theory ของ Brainerd & Reyna ที่ implement เป็นไบต์

ฐานทางทฤษฎี: sign bits คือ SimHash (Charikar 2002) — โอกาสที่บิตตรงกันเป็นฟังก์ชันของมุมตรง ๆ P[bits agree] = 1 − θ/π ดังนั้น Hamming distance คือ ตัวประมาณ cosine แบบไม่เอนเอียง ที่ความแปรปรวนลดลงตามจำนวนบิต → บิต = ขนาดตัวอย่างของการประมาณมุม ซึ่งเป็นเหตุผลที่ตัด “ลดมิติ” ทิ้งทั้งขั้น: ลดมิติ = ลดขนาดตัวอย่าง = พังเร็วกว่าที่ประหยัดได้

บั๊กสี่ตัว — ทุกตัวจบลงที่ loop เก็บกวาดที่ไม่มีวันจบ

  • address ที่ปลดระวางแล้วกลับมามีชีวิต — consolidation คำนวณนิสัยใหม่ทุกรอบแล้วเช็คว่ามีในต้นไม้หรือยัง แต่พอนิสัยถูกเจือจาง address เดิมไม่ได้ชี้ node ที่มีชีวิตแล้วทั้งที่ยัง forward อยู่ → อ่านว่า “ใหม่” แล้วใส่ทับที่เดิม ผลคือ address เดียวมีทั้งตัวที่มีชีวิตและตัวที่ถูก forward — resolve() ตอบตัวหนึ่ง ส่วนที่เหลือทำงานกับอีกตัว
  • node เป็นบรรพบุรุษของตัวเอง — สอง node ที่มาบรรจบที่เนื้อหาเดียวกันเป็นเรื่องปกติ (และตอนนี้ยุบรวมกัน: พอสองความทรงจำจางจนแทนกันได้ มันคือความทรงจำเดียวกันแล้ว) แต่ถ้าตัวที่ชนอยู่ ใต้ ตัวที่กำลังถูกแทน การยุบจะปิดวง
  • D3 เขียนทับเวกเตอร์ของแม่ — ฟังดูถูก แต่วัดแล้วไม่ได้อะไร (แม่อยู่กลาง cluster ตัวเองอยู่แล้ว) สิ่งที่มันซื้อมาคือ address ของบรรพบุรุษเปลี่ยนทุกครั้งที่ยุบ พร้อม alias chain และ collision ข้างบนทั้งหมด ยกเลิกแล้ว — ความซับซ้อนที่แลกความถูกต้องมาโดยไม่คืนอะไรที่วัดได้ ไม่ใช่ trade-off
  • การนึกซ้ำไม่ป้องกันการเจือจาง — retrieval_strength เสื่อมตามเวลา การเรียงเหยื่อด้วยมันอย่างเดียวทำให้ความทรงจำที่ถูกนึกถึงสิบกว่าครั้งถูกยุบทิ้งเมื่อของรอบตัวหมด use_count ไม่เสื่อม — ในภาษาของ Bjork นั่นคือ storage strength และการดึงกลับมาใช้ทำให้มันเพิ่ม ของที่นึกถึงบ่อยจึงไม่ใช่แค่หาง่ายขึ้น แต่หายยากขึ้นด้วย
และการยุติของ loop ไม่ใช่เรื่องบังเอิญอีกต่อไป

ทุกก้าวของการเก็บกวาดต้อง คืนไบต์ หรือปลดระวาง node ที่มันทำงานด้วย ก้าวที่ไม่ทำทั้งสองอย่างจะถูกเลือกซ้ำทันทีและตลอดไป จึงถูกกันออกไป → บั๊กใน rung หนึ่งเสียแค่หนึ่งก้าว ไม่ใช่ทำให้ agent ค้าง

06สิ่งที่ผมเปลี่ยนใจ และบั๊กที่ test จับได้

ส่วนนี้สำคัญกว่ารายการงานที่เสร็จ — ทุกข้อคือของที่ถ้าไม่เจอ จะกลายเป็นระบบที่มั่นใจในสิ่งที่ผิด

  • บันไดเดิมผิด — ร่างแรกมี “ลดมิติ” และวาง binary ท้ายสุด วัดแล้วเห็นว่าทั้งคู่ผิด แก้ตามผลวัด (§03)
  • จุดเข้าของการเดินอยู่ผิดที่ — ร่างแรกให้เริ่มจากราก Conway ชี้ว่าคนเริ่มที่ชั้น general event ทั้งถูกกว่าเชิงหลักฐานและถูกกว่าเชิงต้นทุน (ชั้นบนแยกแยะอะไรไม่ค่อยได้)
  • D3 ไม่ได้ทำตามสเปกตัวเอง — มันลบ node แล้วชี้ต่อ แต่ไม่เคยยุบเวกเตอร์เข้า centroid ของแม่จริง = การลบที่มี forwarding pointer เฉย ๆ แก้แล้ว และการแก้ทำให้ D4 มีงานจริงเป็นครั้งแรก
  • fidelity รายงานสูงกว่าความจริง — เก็บค่าสะสมต่อ address ทำให้ hop แรก (int8 แทบไม่เสีย) ถูกรายงานแทน address ที่ผ่าน binary ไปแล้ว ตอนนี้เก็บ cosine ต่อ hop แล้ว compose ตอนอ่าน เพราะสองขั้นที่เก็บได้ 0.9 ต่อขั้น ไม่ได้เก็บ 0.9 รวมกัน
  • บันไดกับ D3 อีกรอบ — ดู §05 ทั้งหัวข้อ ทุกข้อมาจากการรันทั้งระบบ ไม่ใช่จาก unit test
  • consolidation ตกผลึกผิดตัวสนิท — รอบแรกมันสร้างนิสัยจากกองงานสะเปะสะปะ 5 อย่างใต้หัวข้อเดียวกัน แล้วพลาดกิจวัตรที่ทำซ้ำ 6 วันจริง ๆ สองสาเหตุ: content addressing ยุบเหตุการณ์ที่เหมือนกันเป๊ะเหลือ node เดียว (เลยนับเป็นครั้งเดียว) และ coherence ที่วัดกับ centroid ถูกดันสูงโดยหัวข้อของแม่เอง
ข้อจำกัดที่ต้องรายงานคู่กันเสมอ

Resolution.fidelity เป็น ขอบล่างที่ปลอดภัย ไม่ใช่ค่าที่วัดได้ มันหลวมมากหลังหลายขั้น (อ่าน 0.0 ได้ทั้งที่เวกเตอร์ยังอยู่ใน cluster ถูก) → ใช้ตัดสิน D3/D4 และลง audit log ได้ ห้ามรายงานเป็น M1 M1 ต้องวัดกับ ground truth ใน bench ตามบทเรียนเดิม: ห้ามให้ component ตั้งราคาผลงานตัวเอง

08สามข้อที่ต้องให้ Nin เคาะ

  1. CORE เริ่มต้นมาจากไหน

    เขียนมือตอนสร้าง agent (persona เริ่มต้น) แล้วให้ตกผลึกเพิ่มเอง หรือให้เกิดจากประสบการณ์ล้วน? ตอนนี้ CoreSet.admit() รองรับทั้งสองทาง แต่ยังไม่ได้เลือก

  2. branching factor และเกณฑ์แตก/ยุบ node

    ตอนนี้ตั้ง MAX_CHILDREN = 12 ไว้เป็น default พร้อมหมายเหตุว่าเป็นค่า calibration — เป็นตัวที่กำหนดว่า beam มองไม่เห็นอะไรบ้าง บล็อกการ tune ของ A9–A11

  3. เกณฑ์การตกผลึกนิสัย

    ตอนนี้ MIN_REPEATS = 4 และ COHERENCE = 0.55 ทั้งคู่เป็นค่าที่ตั้งเอง ต้อง tune บน dev seed เท่านั้นตาม N-15 — ตั้งผิดแล้ว agent จะสร้างนิสัยจากเรื่องบังเอิญ ซึ่งแก้ยากเพราะนิสัยเป็น resident และห้ามเจือจาง
